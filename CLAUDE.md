# Living World — симуляция живого мира в зомби-апокалипсисе

## Суть проекта
Процедурно генерируемый большой мир (по наполнению похож на Чернарусь из DayZ): города, деревни, дороги, дома, леса, вода.
Мир **живёт сам по себе**: люди, зомби, животные и птицы действуют автономно, есть время суток, погода, времена года.
Каждый объект имеет уникальный id, за любым можно наблюдать и читать его историю.
Главная цель — **эмерджентные уникальные истории**: дружба, предательство, месть, группы, лидеры, интриги.
Игрок может наблюдать за миром или вселиться в любое живое существо.

Приоритет: **симуляция важнее графики**. Сначала 2D (кружочки), 3D потом.

## Стек
- C++20, CMake
- raylib (окно, 2D/3D, поверх OpenGL)
- Dear ImGui (через rlImGui) — инспектор, панели, лог событий
- EnTT — ECS
- FastNoiseLite — генерация рельефа
- Зависимости подключать через CMake FetchContent
- Unity и другие тяжёлые движки не используем

## Архитектура (обязательные принципы)
1. **Симуляция полностью отделена от рендера.** Код в `src/sim/` не знает о raylib/ImGui. Он должен уметь работать headless.
   Рендер (`src/render/`, `src/ui/`) только читает состояние мира.
2. **ECS (EnTT).** Каждое существо, предмет, машина, здание — сущность с компонентами. Id стабилен и уникален за всю жизнь мира.
3. **Фиксированный тик симуляции**, независимый от FPS. Ускорение времени: пауза, x1, x10, x100.
4. **Уровни детализации симуляции (LOD):** рядом с камерой — полная симуляция каждый тик; далеко — грубая, редкими шагами
   (агрегированные результаты: «группа прошла 3 часа, потеряла одного»).
5. **Детерминизм:** один seed → один и тот же мир. Весь рандом через собственный RNG мира, не `rand()`.
6. **Сохранение/загрузка мира.**

## Системы, рождающие истории
- **Нужды:** голод, жажда, усталость, страх, одиночество, здоровье.
- **Черты характера:** смелость, жадность, альтруизм, агрессия, лидерство и т.д.
- **Utility AI:** существо выбирает действие с наилучшей оценкой с учётом нужд и черт (не деревья поведения).
- **Память:** существа помнят значимые события с участием других (кто помог, кто бросил, кто убил близкого).
- **Отношения:** у пар есть доверие, симпатия, долг, обида; меняются от событий. Отсюда группы, лидеры, изгнания, месть.
- **Дефицит ресурсов:** еды, воды, патронов, топлива, медикаментов всегда мало — это источник конфликтов.
- **Внешнее давление:** зомби, зима, болезни, ивенты.
- **Ивенты:** военный конвой, крушение вертолёта, падение припасов и т.п. Ивент — не сценарий, а «камень в воду»: создаёт ценность/угрозу, дальше работают системы.
- **Рассказчик (как в RimWorld):** следит за темпом, подбрасывает события при затишье, даёт передышку при хаосе.
- **Летопись:** журнал значимых событий, привязанных к id. По любому id можно прочитать биографию.

## Структура
```
src/
  sim/      — мир, ECS-компоненты, системы, ивенты, летопись (без зависимостей от графики)
  sim/gen/  — генерация карты: рельеф, вода, поселения, дороги, улицы, дома
  render/   — отрисовка мира (сейчас 2D)
  ui/       — ImGui-панели: инспектор id, лог событий, управление временем
  main.cpp
docs/       — заметки по архитектуре и дизайну
```

## План (дорожная карта)
1. Каркас: CMake + raylib + ImGui + EnTT, окно, камера с зумом/панорамой.
2. Генерация 2D-карты: рельеф, вода, леса, города, деревни, дороги между ними, дома.
3. Время суток, времена года, погода.
4. Люди-кружочки с нуждами, движением, поиском пути (A* по сетке).
5. Зомби и животные, бой, смерть, лут.
6. Память, отношения, группы.
7. Ивенты и рассказчик.
8. Инспектор по id и летопись.
9. Вселение в существо (управление).
10. Машины.
11. 3D (простая полигональная графика, текстуры-фото).
12. Удалённое наблюдение (сервер симуляции + клиент), позже стриминг.

## Правила работы
- Делать по одному этапу за раз; после этапа проект должен собираться и запускаться.
- Перед крупными изменениями кратко описывать план.
- Обновлять этот файл и `docs/`, когда меняется архитектура или завершается этап (отмечать прогресс ниже).
- Код и комментарии — понятные; имена на английском, общение и документация — на русском.
- Git: каждый этап делается в отдельной ветке с латинским названием (`stage-3-time-weather` и т.п.).
  Когда этап закончен — коммит и слияние ветки в `main`.

## Сборка и запуск
CMake в PATH нет — он берётся из Visual Studio 2026, скрипт находит его сам.
- `scripts\build.ps1` — конфигурация и сборка (`RelWithDebInfo`); `-Run` — запустить, `-Test` — тесты, `-Config Debug|Release`, `-Clean`.
- `build\bin\RelWithDebInfo\living_world.exe [--seed N]` — приложение. `--view X Y ZOOM --screenshot FILE.png` — поставить камеру, сохранить снимок окна и выйти: так можно посмотреть на результат, не управляя окном.
- `build\bin\RelWithDebInfo\lw_headless.exe --seed N --ticks N` — прогон без окна, печатает сводку по карте и хеш состояния (проверка детерминизма).
- Версии зависимостей зафиксированы в `cmake/Dependencies.cmake`.

Архитектурные решения и правила детерминизма — в `docs/architecture.md`. Главное:
- сущности создавать только через `World::create()`; ссылаться на них по `EntityId`, а не по `entt::entity`;
- рандом — только `world.rng(RngStream::...)`;
- каждый новый компонент, влияющий на будущее мира, добавлять в `World::stateHash()`;
- порядок шагов генерации карты и вызовов рандома в них не менять без нужды: это меняет карты всех seed.

## Прогресс
- [x] Этап 1 — каркас: сборка, окно, камера, фиксированный тик со скоростями x1/x10/x100, стабильные id, RNG, headless-прогон, тест детерминизма. По миру блуждают временные тестовые существа (`WanderSystem`, убрать на этапе 4): о карте они не знают и ходят по воде.
- [x] Этап 2 — генерация карты (`src/sim/gen/`): рельеф, море, озёра, реки, леса, поля, города и деревни с названиями, дороги между ними, улицы и дома. Поселения и здания — сущности. Карта рисуется текстурами-чанками. Описание шагов — в `docs/architecture.md`.
